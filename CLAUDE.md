# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A local, read-only web dashboard for CoinDCX futures pairs that runs plain statistics on each coin's price momentum. Nothing is trained: there are no ML models, risk models or forecasts. For each tracked coin and each horizon (1h, 4h, 1d, 3d) it serves the last move in volatility units, an event study of what followed similar moves, persistence tests (variance ratio, IC), a Long/Short/Neutral signal from those, and supporting signals (taker flow, beta-adjusted move against the benchmark, RSI, EMA stack, ranges, volatility, volume, funding, order book). A `futurecast backtest` command separately replays two rule-based setups (fair-value-gap setups, wedge breakouts) on history; they are not on the dashboard. It must never trade: there are no API keys, no order routing, and `AppConfig.enforce_zero_execution_policy()` (`config.py`) refuses to start if `safety.execution_enabled` is true or `safety.air_gapped` is false. Keep it that way.

The user removed the earlier LightGBM/XGBoost/CatBoost setup models, the trade-risk quantile models, the HMM volatility regimes and the residual-alpha ensemble on 2026-10-17 ("throw away all the logic for risk analysis and xgboost"). Don't bring models back without being asked.

## Commands

Python 3.12, managed with `uv`; the page is Svelte 5 + Tailwind 4 built with Vite in `web/` (npm, Node 24 from `mise.toml`). No linter or formatter is configured. Tasks are in `mise.toml`:

```bash
mise dev                                           # Vite on http://localhost:5000 (hot reload, proxies /api and /ws) + backend on 127.0.0.1:5001
mise run dev:api -- --offline                      # one half only; FUTURECAST_API_PORT / FUTURECAST_WEB_PORT change the ports
mise run build                                     # web/ → web/dist, which the backend serves on /
mise run check                                     # svelte-check (types)
mise run test                                      # same as uv run pytest -q

uv run pytest -q                                   # full suite (~90 tests, ~2s, no network)
uv run pytest tests/test_web.py -q                 # one file
uv run pytest tests/test_web.py::test_web_serves_the_built_page -q   # one test
uv run pytest -k persistence -q                    # by name

./run.sh                                           # dashboard on 0.0.0.0:8000 (wraps `uv run futurecast`; builds web/dist if missing)
uv run futurecast --host 127.0.0.1 --port 8765     # local only, other port
uv run futurecast --offline                        # synthetic random-walk candles, no network

uv run futurecast backtest B-ETH_USDT              # backtest the setup rules: 15m entries, 1h context, 2 years, A+, 3R
uv run futurecast backtest B-ETH_USDT --entry 5m --context 1h --days 365 --target 4 --grade all --csv trades.csv
uv run futurecast backtest B-ETH_USDT --strategy wedge --entry 4h --target measured   # wedge breakouts, one chart (1h default)
```

Runtime state lives in `~/.futurecast`, or `$FUTURECAST_HOME` if set (`paths.py`). When running the server to check a change, point `FUTURECAST_HOME` at a temp folder so the user's watchlist isn't touched. Tests already do this through an autouse fixture in `tests/conftest.py`, which also stubs the Binance catalog so tests stay offline. Older installs still have `<home>/models/` and `<home>/logs/forecasts/`; nothing reads them.

## Architecture

**Data flow.** `cli.py` → `publisher/web_server.py` (FastAPI app, REST + `/ws` WebSocket) → `publisher/multi_manager.py`, which is the hub. `MultiCoinStreamManager` holds one `SymbolWorker` per tracked coin and runs the stream loop: live price and order book on every poll (~3s), and candles plus statistics only when a 15m or 1h candle closes. Every snapshot is pushed to browsers as a `FORECAST_UPDATE` WebSocket message (the name is historical). Snapshots and API responses carry only what the page reads (the user had all unused code and fields removed on 2026-10-17); add a field when the page starts using it. `/api/coindcx/futures` returns the whole catalog and the add-pair drawer (`Sidebar.svelte`) searches and filters it.

**Symbols.** CoinDCX names (`B-SOL_USDT`, `I-BTC_INR`) are the IDs everywhere: API, persistence. All market data (candles, settled funding rates, prices, order books) actually comes from the Binance USD-M perpetual behind the pair (`ingestion/binance.py`: `B-SOL_USDT` → `SOLUSDT`, `B-1000PEPE_USDT` → `1000PEPEUSDT`, INR pairs → their USDT perpetual). CoinDCX is never called; the add-coin catalog (`ingestion/coindcx_catalog.py`) is Binance perpetuals renamed to CoinDCX form plus a curated registry. Each coin gets one sector-aware benchmark (`ingestion/factory.py`: `get_symbol_sector`, `resolve_benchmark`, e.g. meme coins → DOGE, leaders and unlisted coins → BTC), downloaded and aligned with it (`SymbolWorker.benchmark`). A coin is never its own benchmark (BTC → ETH): its candle columns would collide.

**History.** `SymbolWorker.load_history` downloads `HISTORY_BARS` closed candles per chart in `CHART_MINUTES` (17,280 15m ≈ 180 days, 17,520 1h ≈ 2 years) for the coin and its benchmark, the coin's settled funding rate on `FUNDING_CHARTS` (1h), aligns them (`ingestion/storage.align_cross_asset_data`, columns `{SYMBOL}_close` etc.), and computes the statistics. `status` goes pending → queued → downloading → ready (or failed, with `error`); `progress` (label, step of steps, candles done of total, fraction) feeds the dashboard's progress bar. It runs in a thread executor behind one asyncio lock (one coin at a time, `MultiCoinStreamManager.schedule_load`); in live mode coins are queued on add and at stream start, and `POST /api/coins/{symbol}/reload` requeues one. After that `refresh_candles` appends each closed candle (keeping `HISTORY_BARS`) and reruns `_update_stats`; it does nothing until the worker is ready. Offline mode (`load_synthetic`) fills `OFFLINE_BARS` random-walk candles per chart and is ready at once.

**Momentum statistics** (`stats/momentum.py`; read its module docstring before changing anything). `MomentumSpec.horizons` maps 1h and 4h to 4 and 16 15m candles, 1d and 3d to 24 and 72 1h candles. Per horizon of h candles:
- **Move:** z = (log return over h candles) / (σ √h), σ the rolling std of one-candle log returns over `vol_days` (14) of candles, at least 5 horizons (`vol_window`); `percentile` ranks the latest z against all earlier z; `typical_move_pct` is σ√h.
- **Event study** (`event_study`): past z split into `quantiles` (5) by full-history quantiles; for the current z's quintile: n, `windows` (n / h, non-overlapping count), mean/median simple forward return over the next h candles, hit rate, 95% interval, older/newer half means, and the same over all windows. The interval uses `long_run_variance` with lag h − 1: Hansen–Hodrick (equal-weight autocovariances, exact for h-candle overlap; Bartlett/Newey–West with lag h understates the variance by ~30%), falling back to Newey–West if non-positive. `test_overlapping_windows_get_the_right_standard_error` pins it.
- **Persistence:** `variance_ratio` (Lo–MacKinlay VR(h), heteroskedasticity-robust z*) → `character` trending / mean_reverting / random at 5%; `information_coefficient` of z against the next h candles' volatility-scaled return, with the same overlap-corrected t.
- **Signal** (`momentum_signal`): `reason` is checked in order flat (middle quintile) → few (event study missing or fewer than `min_windows` 30 non-overlapping windows) → noise (95% interval includes 0) → fees (|mean| ≤ `round_trip_pct`, 2 × `taker_bps` = 2 × 8.85 bps, CoinDCX taker with GST, same as `SetupSpec.taker_bps`) → unstable (older and newer halves disagree in sign) → edge (LONG/SHORT). `kind` is continuation when the signal follows the move, reversal when it fades it. `signalVerdict` in `web/src/lib/momentum.ts` re-states these reasons in words; keep the two in sync.
- Also per horizon: `flow` (taker-buy share of quote volume over the last h candles, and its percentile) and `versus` (beta from one-candle returns over the vol window; excess = coin move − β × benchmark move).

It is an in-sample event study, not a backtest: the current stretch is part of the history it averages over. On real BTC/ETH/SOL/BAT/INJ/DASH history (Oct 2026) every horizon read NEUTRAL, mostly "noise".

**Supporting signals** (`stats/signals.py`, `signals_view`): Wilder RSI(14) on 15m and 1h, EMA 20/50/200 stack on 1h (up / down / mixed, price vs EMA200), range position over 24h (15m) / 7d / 30d (1h), last-day realized vol from 15m candles and its percentile, last-24h quote volume vs the median of the 30 days before (1h), funding rate and its percentile over 90 days (1h). Anything the candles can't support is None (e.g. funding offline).

**Setup rules (backtest only).** Not on the dashboard and not trained:
- **Rules** (`features/structure.py`, `features/setups.py`): swing points (`swing_len` candles each side, so a swing is only known `swing_len` candles later), market structure (a *close* beyond the latest unbroken swing: BOS with the trend, CHoCH against it) and fair value gaps (first candle's wick and third candle's wick don't overlap; a gap stays a zone until a close through its far side or `max_age` candles). The charts are `SetupSpec.ltf_minutes` (entries) and `htf_minutes` (context), 15m in 1h by default; every count in `SetupSpec` is in candles of its own chart. `find_setups` turns every entry-chart CHoCH whose move left a gap into a setup: limit at the gap's midpoint, stop just past the pullback's extreme, take-profits at `SetupSpec.targets` (2R, 3R, 4R). Two context-chart checks (context trend the trade's way; pullback into a standing context gap) make it grade "A+", else "B".
- **Outcomes** (`labels/setups.py`): the limit waits `fill_window` entry candles and is cancelled if price first runs `cancel_r` (3R) away; a filled trade wins on take-profit before stop, the fill candle can only stop it out, both in one candle is a loss, and `max_hold` candles without either is a timeout at that close. Results are in R; anything the data doesn't cover yet stays open (NaN).
- **Backtest** (`backtest.py`): the rules alone, replayed like one account: only the chosen grades (A+), one setup at a time, a fixed % of equity risked per trade, compounding, after fees; reports win rate vs break-even, R before and after fees, profit factor, drawdown, streaks, monthly and per side. Results on 2 years to Oct 2026 (A+, 3R, per trade after fees): 15m/1h with per-leg fees ETH +0.06R, SOL −0.01R, BAT +0.01R, BTC −0.56R; other chart pairs worse. Before fees A+ setups are near 0R almost everywhere.
- **Costs** (`SetupSpec.maker_bps`, `taker_bps`, `slippage_bps`, `round_trip`; `labels.setups.break_even`): per leg, by how the trade ended. The limit entry and a win's take-profit pay maker, a stop pays taker plus slippage, a timeout taker. Defaults are CoinDCX USDT-M futures with 18% GST (0.0295% / 0.0885%) and 2 bps of stop slippage (assumed). The CLI takes `--maker`, `--taker`, `--slippage` in bps.
- **Wedge breakouts** (`features/wedges.py`, `labels/wedges.py`, `backtest.backtest_wedge_candles`, `--strategy wedge`): one chart. Lines through the latest two swing highs and two swing lows known by the previous candle, converging, apex 10–30 candles past the breakout, no close outside them since the first pivot; a close beyond a line breaks out (A+: volume 1.5× its 20-candle mean and body > ATR(14)), watched by one state machine per chart: a retest within `retest_tolerance` of the line within `retest_window` candles, a close that far back inside fails it, and the retest candle or the next must close the trade's way in its top/bottom half. Market entry at that close, stop `stop_atr` ATR past the retest, targets 2R, 2.5R and `"measured"`, stop to `breakeven_stop` after `breakeven_r`. `BacktestConfig.max_leverage` (CLI default 5 for wedges) shrinks the risk of too-tight stops. Results, all grades, 2R after fees: 15m −0.2 to −0.5R, 1h −0.04 to −0.4R, 4h over 6 years and 10 coins −0.02R on 212 trades; ~0R before fees everywhere.

**Candle cache.** `ingestion/cache.py` `CandleCache` keeps closed candles on disk in `<home>/cache/candles/<BINANCE_SYMBOL>_<interval>.parquet`, keyed by Binance market so pairs and benchmarks share files (the dashboard and the backtest CLI share them; `CACHE_BARS` 120k rows). Each file records the span of open times it fully covers (Parquet metadata `covered_from`/`covered_to`; 0 means back to the listing), and `BinancePublicClient._closed_klines` downloads only what lies outside that span. Clients get a cache only when constructed with one (`multi_manager._binance_client` does, from `assets.storage`), so tests with a bare client stay uncached. Funding rates are not cached on disk.

**Watchlist.** `<home>/tracked_symbols.json` holds the coins the user added and is rewritten on every add/remove. There are no default coins: with nothing saved the watchlist starts empty. `create_app(initial_symbols=...)` overrides the saved list, which tests use.

## Gotchas

- **Config:** `load_config()` reads `<home>/config/assets.yaml` and `safety.yaml`, not the repo's `config/` folder. The repo YAML files only document the defaults; the real defaults are the pydantic models in `config.py`. Unknown keys in old home config files are ignored.
- **Window units:** positions count candles, not clock time; gaps the aligner dropped are stepped over. `MomentumSpec.vol_window` converts `vol_days` to candles of the horizon's chart. `SetupSpec` counts `ltf_*`, `fill_window` and `max_hold` in entry candles and `htf_*` in context candles.
- **History length vs. signals:** the event study's power comes from history. 180 days of 15m candles give ~1,080 non-overlapping 4h windows (~216 per quintile); 2 years of 1h give ~48 non-overlapping 3d windows per quintile. Shortening `HISTORY_BARS` makes "few"/"noise" more common; it doesn't make signals more reliable.
- **Timestamps:** under pandas 3 a candle index may be stored in microseconds, so `.asi8` is not nanoseconds. Compare candle times across frames with `features.setups.close_times` (it converts to ns), not raw `asi8`.

## Frontend

Svelte 5 (runes) + Tailwind 4 in `web/` at the repository root, built by Vite (no SvelteKit, one page). `web_server.py` serves `web/dist` (`WEB_DIST`, overridable through `create_app(web_dist=...)`): `/` is `index.html` with `Cache-Control: no-cache`, `/assets/*` are Vite's hashed files cached as immutable, and without a build `/` answers 503 with how to make one. In development use `mise dev`; the Vite server proxies `/api` and `/ws` to the backend, so the page code always uses same-origin URLs.

- `src/lib/live.svelte.ts`: the one `$state` object `app` (coins, selected horizon `timeframe`, open cards `expanded`, connection, catalog, drawer), the REST calls and the `/ws` stream. Components read it and update on their own; there is no manual re-rendering.
- `src/lib/momentum.ts`: the statistics in words (`signalVerdict`, `moveText`, `afterText`, …). `src/lib/format.ts`: number formatting. `src/lib/types.ts`: the snapshot fields the page reads.
- `src/components/`: `Header`, `Toolbar` (title, summary, horizon selector), `Watchlist` → `CoinRow` → `CoinDetails`, `Sidebar` (add pair), `Glossary` (footer cheat sheet), `Tooltip` (one floating tooltip for every `data-tooltip` / `data-tooltip-title` attribute, through delegated events), `Icon`.

**Styling.** Colors are CSS custom properties in `src/app.css`, defined twice: light in `:root` and dark in `:root[data-theme="dark"]`. Any new color token needs both, plus a `--color-*` line in its `@theme inline` block to get Tailwind utilities (`bg-surface`, `text-muted`, `border-rule`, …); Tailwind's default palette is switched off. Breakpoints are the page's own: `max-lg:` < 1180px, `max-md:` < 980px, `max-sm:` < 720px. Markup uses utilities; shared pieces (`.btn`, `.icon-btn`, `.pill`, `.val-*`, `.row-grid`, `.book-bar`) are in `@layer components` in `app.css`, and things utilities can't say (the open card's HUD brackets, hover gradients, the phone grid areas, the tooltip) are in component `<style>` blocks. Cascade gotchas: utilities beat the components layer, so don't pair a `.val-*` class with a `text-*` utility on one element; unlayered component `<style>` rules beat every utility, so don't set `display` there on something a `max-*:hidden` utility hides. The look is a Cyberpunk 2077 pause menu: square corners, caps labels, red (`--text-muted`) for labels only, cyan (`--accent`) for selection. Numbers and paragraphs that should look quiet use the neutral `--text-dim` (`.val-muted`, `text-dim`), never `--text-muted`, so they don't read as negative. All text is Rajdhani (`--font`, self-hosted in `src/assets/fonts/` with its OFL license). It has no tabular figures, so number columns only roughly align, and text that ticks in place (the header clock) needs a fixed `min-width`. The theme is set before first paint by an inline script in `index.html` and toggled in `Header.svelte`.

**Coin card.** The horizon selector (`app.timeframe`, default 4h) drives every horizon-dependent cell and the column heads.
- **Row** (`CoinRow.svelte`): signal pill (`signalVerdict`), Move (return, z, percentile), Next (event-study mean, share up, coloured only when its 95% interval excludes zero), Character (variance ratio), Taker flow (bar + percentile), Order book. The price flashes green/red when an update moves it.
- **Expanded** (`CoinDetails.svelte`): the verdict block (the selected horizon's pill, the reason in words, five numbers at full contrast: move, next after similar, rose afterwards, vs benchmark, taker buys; a green/red panel for Long/Short), every horizon in a table (clicking a row selects it), the supporting signals, then the footer (history span, Reload history / Retry download, CoinDCX link, Remove). Percentiles display through `pctile` ("<1st", ">99th" at the ends).
- **Order book:** display-only; no statistic uses it.

**Checking UI changes.** `--offline` renders everything from random-walk candles (all NEUTRAL, no funding). For real numbers, run the server live with `FUTURECAST_HOME` pointed at a temp folder and copy `~/.futurecast/cache/candles/<COIN>USDT_{15m,1h}.parquet` plus the benchmark's into `<temp home>/cache/candles/` first, so only the newest candles download. `FUTURECAST_HOME=<temp> FUTURECAST_API_PORT=8765 FUTURECAST_WEB_PORT=5199 mise dev` keeps clear of the user's own `mise dev` (5000/5001) and of a dashboard they have running on :8000 (which serves `web/dist` as last built, so it shows source edits only after `mise run build`; its Python is whatever it started with). View the user's dashboard only: don't add or remove coins there. To preview signal states, run `futurecast.stopLive()` in the page console (stops the stream so updates don't overwrite your edits), then edit `futurecast.app.coins[...]`: the page re-renders by itself.
